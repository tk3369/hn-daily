    Android 17 is the first since 3.x to add new APIs without releasing to the AOSP

    GrapheneOS flags the milestone: Android 17 ships new APIs with no AOSP source drop — the first since Honeycomb 3.x. It's the visible tip of a two-year retreat — embargoed patches, delayed upstreams, attestation pressure on custom ROMs — and the thread reads it as Google closing the open era.

    • What it is
      • New APIs in Android 17, no AOSP source release
      • Follows embargoed patches, delayed upstreams, attestation squeeze
    • HN take
      • Open source was strategy, not philosophy — 'they regret Android being open'
      • Post-Epic loss, Google is rebuilding the Apple walled garden
    Source: grapheneos.social · Discuss: HN Discuss · 913 pts / 500 comments

    What HN commenters are sayingThe top thread is strategy-vs-philosophy: when Android launched, open source got phone makers and carriers on board; today it's a net negative for Google, so they're changing it — well-run companies aren't zealots. A minority argues keeping AOSP open is still in Google's interest (free passionate labor, security signals, forks beat alternatives). The sharpest legal read: after losing to Epic, Google is moving toward Apple's walled-garden model because a locked-down platform wins those lawsuits.

    How to Write with an LLM

    Thomas Ptacek's two rules for LLM-assisted writing: (1) never use a single word an LLM suggests — use it as copyeditor, not ghostwriter, because frontier models turn everything into magazine headlines; (2) forbid encouragement — models praise your first draft and you'll double down on impulses you'd normally edit out. Write first, then run problem-finding passes.

    • What it is
      • Rule 1: no LLM-suggested words, ever; Rule 2: no encouragement
      • Write first, then model runs problem-finding passes
    • HN take
      • Thread pivots to commit messages: the WHY belongs there, not a diff summary
      • CI-enforce semantic format + ticket; Claude's gibberish commits prove the point
    Source: sockpuppet.org · Discuss: HN Discuss · 530 pts / 352 comments

    What HN commenters are sayingThe thread's real topic: commit messages. Strong consensus that the message should carry what the diff can't — the why — because a diff-derived summary is redundant. Top practical workflow: enforce semantic-commit plus ticket format in CI, and have the same agent that wrote the code lead with a paragraph of context. The funniest validation of Ptacek's thesis: Claude's actual commit messages ('Realigned the shape of the load-bearing ownership gate') read exactly like the magazine-headline mush Rule One is designed to stop.

    Laya the open source version of Jev

    Laya (laya.convaiinnovations.com) — an open-source version of Jev, the one-shot classifier that beat calling Gemini 2.5 Flash Lite on classification tasks: a bit faster, a bit cheaper, nice consistency. One call, multiple classifiers, no LLM in the loop.

    • What it is
      • Open-source one-shot classifier: faster/cheaper than Flash Lite
      • One call, multiple classifiers; pre-LLM NLP playbook
    • HN take
      • 'Just BERT with more data' vs LLMs generalize better on messy inputs
      • Typed-vs-untyped analogy: LLM is the one-off script, Jev the long-term typed solution
    Source: laya.convaiinnovations.com · Discuss: HN Discuss · 217 pts / 34 comments

    What HN commenters are sayingThe thread relitigates the oldest ML argument of the LLM era. One side (ex-NLP engineers): using LLMs for everything is lazy and wasteful — Jev is 'just BERT with more data,' a wake-up call to go back to basics; the cheapest LLM request is no request. The other: LLMs are less fragile on out-of-distribution inputs, and off-the-shelf is cheaper once you count training, data prep, and labeling time. The typed-vs-untyped-languages analogy lands best: the LLM is the one-off Python script, the specialized classifier is the long-term typed solution.
