    Cloudflare acquires Deno: the whole team joins, the runtime gets one more year, Deploy gets six months

    Deno announces its entire team is joining Cloudflare to work on the Workers and Durable Objects model, including Ryan Dahl's celld effort. The concrete terms matter more than the headline: the Deno runtime gets one year of monthly bug-fix and security releases, then the team's own development ends (it stays open source); Deno Deploy runs six more months before shutdown, with migration help to Workers; JSR keeps operating on Cloudflare infrastructure.

    • The timeline
      • Runtime: supported for one more year with monthly bug-fix and security releases, then team development ends
      • Deno Deploy: six months left, then shutdown; paying customers get migration support to Workers
      • JSR continues, moving onto Cloudflare infrastructure; rusty_v8 support continues toward workerd integration
    • The stated logic
      • Dahl frames it as a progression — runtime, then Deploy, then celld — each step simplifying the layer underneath
      • The target is a programming model where scaling is built in, whether code runs on Cloudflare or your own infrastructure
      • Durable Objects are pitched as a fit for agent harnesses: cheap serverless execution, persistent state, WebSockets
    • Why it matters
      • Deno users have a dated migration decision, not a vague roadmap
      • Cloudflare absorbs a respected runtime team and folds its work into Workers instead of running a rival platform
      • What survives is the model, not the standalone runtime — plan accordingly
    Source: deno.com · Discuss: HN Discuss · 1273 pts / 655 comments

    What HN commenters are sayingReaction splits between genuine affection for the runtime — daily users praise the no-surprises developer experience, the flawless VS Code extension and batteries-included balance — and a plain reading of the sunset clause: unless someone else picks it up, Deno is unsupported after a year. A few initially feared the deal was meant to kill celld as a rival runtime, then corrected themselves on seeing the plan to make workerd an open, self-hostable runtime. The open question in the thread is why Cloudflare is not running with the runtime itself, which many took to be Deno's secret sauce.

    REA gives your coding agent reverse-engineering tools: inspect a program, explain it, rebuild the behaviour

    REA connects to a coding agent and supplies the evidence reverse engineering needs — a handler's instructions, decompiled code and call relationships — so the agent can explain, change or rebuild what a program does. Its worked examples recover Windows Calculator's percentage rules (different branches after + and ×) from the installed app and rebuild them, and extract Chrome's dinosaur-game speed rule from the running script to build an adjustable-speed clone.

    • How it works
      • Setup via an npx command pasted into your coding agent, with a plan shown for approval first
      • Targets: native binaries, JavaScript and Electron apps, and browser or runtime activity
      • REA returns the inspected code and settings; the agent interprets and rebuilds
    • The demos
      • Calculator: one percentage branch divides by 100, the other also multiplies by the first number — recovered from the installed DLL and cross-checked
      • Dinosaur game: start speed 6, +0.001 per update, capped at 13 — read from the running script, then rebuilt with a slider
      • Further case studies include reconstructing a game from its executable
    • Why it matters
      • Shifts reverse engineering from manual decoding to agent-led investigation with primary evidence
      • Useful for interoperability, legacy behaviour and security work — the same reasons the thread asks hard questions about it
    Source: rea.tools · Discuss: HN Discuss · 513 pts / 219 comments

    What HN commenters are sayingTwo questions dominate. First, the sceptical one, asked several ways: what does this do that an agent with Ghidra or radare2 already set up does not? Second, the installation joke: pasting an npx setup command into an agent is described as the next evolution of curl-piped-to-bash — approval plan notwithstanding. Enthusiasts are already planning to try it on open game-engine projects, and one long comment argues the work gets more important as frontier models get more locked down, pointing to legal exemptions for reverse engineering. The value question is left open; nobody in the top thread reports a head-to-head comparison.

    Show HN: Carrier-Explode decodes iPhone, Pixel and Galaxy carrier settings — APNs, VoLTE, 5G, compared

    Carrier-Explode extracts the carrier configuration buried in iPhone, Pixel and Galaxy firmware and makes it searchable: look up a carrier's APNs, VoLTE, Wi-Fi Calling and 5G settings per phone, pick features and see which carriers support them, and diff any two versions or carriers to see what a build changed. Version 2.0 ships a reworked backend, and everything is available as JSON via an API or as a daily CC0 dataset.

    • What you can do

      • Comparisons between versions and carriers show what each build changed
    • Open by default
      • Full data via API as JSON
      • Daily dataset released CC0
      • A wiki documents each carrier format; decoder contributions invited
    • Why it matters
      • Carrier settings decide real behaviour — roaming, calling features, 5G — and are normally opaque inside firmware

    Wallace and Gromit, 90% alone: Nick Park made A Grand Day Out mostly by himself, over most of a decade

    Animation Obsessive reconstructs how Nick Park's first Wallace and Gromit film began in 1982 as a graduation project and consumed most of the 1980s: Park estimates he did about 90% of it himself, commuting by bus, out of grant money, with seven minutes finished after four years — until Aardman put him on salary and let him finish it in spare hours behind a curtain. It premiered in Bristol in November 1989 alongside Creature Comforts, took the BAFTA, and defined his style: Gromit's expressions carried entirely by his eyes after the character's dialogue was cut in the first week.

    • The grind, measured
      • Began 1982 as a student film; Park thought ten minutes would take six months
      • One script paragraph — build a rocket — took a year and a half to shoot
      • By 1985: over four years in, about seven minutes of a roughly 24-minute film done
    • Decisions that stuck
      • Gromit was originally a cat, and had dialogue; both changed early in the shoot
      • Wallace's wide mouth grew out of animating the word cheese
      • No video assist: results unseen until film came back a week later
    • Why it matters
      • The case for learning by making: the style that took over Aardman was formed alone, on one over-ambitious film
      • A useful corrective to the overnight-success reading — the premiere was 1989, the start was 1982
    Source: animationobsessive.substack.com · Discuss: HN Discuss · 246 pts / 38 comments

    What HN commenters are sayingWarm and personal: people recall watching with their fathers decades ago, and several say they had no idea the film was a solo school project rather than a full studio production — the bus commute and the years behind a curtain reframe it for them.     Telegram Desktop flaw chained a clicked link to arbitrary file theft — and full account takeover

    A security write-up chains two defects in Telegram Desktop (through 7.2.8, fixed in 7.2.9; CVE-2026-107181, CVSS 8.1): clicked tg:// links are handed to the already-running instance as semicolon-separated text without escaping, so one link can smuggle in extra commands; and an internal interpret: scheme — built to publish Telegram's own releases — reads a named file and sends it to a chat with no confirmation or authorization check. Plant an instruction file via an auto-downloaded group attachment, link to it, and the chain reads arbitrary local files; aimed at the tdata session files, with no local passcode set, that is account takeover.

    • The chain
      • Unescaped separator in the local-socket handoff turns one clicked link into several commands
      • interpret: reads any file named in an instruction file and sends it to a channel or supergroup, no prompt
      • Instruction files land at predictable paths via default group auto-download (up to 8 MiB)
    • Scope (researcher-reported)
      • Affected through 7.2.8, confirmed on Windows; fixed in 7.2.9
      • CVE-2026-107181, CVSS 8.1 High
      • Session theft needs the default no-passcode setup; a local passcode changes the key derivation
    • Why it matters
      • Update Telegram Desktop to 7.2.9 or later, and set a local passcode
      • A textbook composition failure: a safe-from-the-command-line feature became dangerous once reachable from a link
    Source: beaksec.github.io · Discuss: HN Discuss · 243 pts / 128 comments

    What HN commenters are sayingThe submitter's own framing leads: the headline-worthy part is not just account takeover but arbitrary theft of any user-readable file, which the original write-up underplays. From there the thread widens — one camp says this is a desktop-OS problem, since any user process can read any user file and proper per-app isolation would blunt it; another rehearses Telegram's longer security reputation, from phone-number-tied accounts to optional-only 2FA. Defenders and critics mostly talk past each other; on the narrow point — patch, and the internal scheme should never have been link-reachable — there is no real dispute.

    Danish CPR breach: access to 8.8 million records reportedly stood behind the password '123456'

    Copenhagen Post reporting, via Politiken, says the breach of Denmark's Central Person Register ran through a small private IT company's legitimate search access — and that at least three of its accounts, including an admin account, used the password 123456, with a former employee's leaked credential and no multi-factor authentication in the hacker's account of the entry. About 8.8 million records — names, addresses and CPR numbers, including deceased and emigrated people — were accessed over roughly three weeks in September before detection in early October.

    • What happened (reported)
      • Attackers misused a vetted company's authorised CPR search access; the register itself was not broken into
      • About 8.8 million of roughly 11 million records accessed; Denmark's living population is about 5.9 million
      • Access has been blocked, police are investigating, and the case is with the data protection agency
    • The credential claim
      • Hacker told Politiken the entry was a former employee's leaked password: 123456 — not officially confirmed
      • Follow-on reporting says at least three accounts at the company shared that password, one of them admin, with no MFA
      • Volume over weeks was not flagged — the monitoring question is still open
    • Why it matters
      • CPR numbers are persistent identifiers; they cannot be reissued like a password, so the exposure is durable
      • Delegated access makes the weakest intermediary's password hygiene the national perimeter

    Eye of Sauron (2024): detecting hidden spy cameras at 20+ metres from memory electromagnetic radiation

    This USENIX Security 2024 paper presents ESauron, a proof-of-concept that detects wireless, wired and offline spy cameras alike by listening to electromagnetic radiation from the camera's own memory. The mechanism: every camera digests raw images (encoding, compression) in read-write memory before storage or transmission, and scene changes spike that workload, producing EMR patterns at the memory clock frequency. Deliberately stimulate scene changes, sense the surge, then pinpoint the device. Across 50 camera products the authors report 100% detection after four stimuli, at ranges over 20 metres even through blockages.

    • The side channel
      • Video digestion in inbuilt memory emits EMR tied to processing workload
      • Stimulated scene changes create a detectable, repeatable signature
      • Works on offline cameras too, since it targets processing, not transmission
    • Results (paper-reported)
      • 50 camera products tested; all detected after only 4 stimuli
      • Detection range exceeds 20 metres, including with blockages
      • Locations pinpointed accurately for all tested cameras
    • Why it matters
      • Most detectors hunt radios or lenses; this hunts the computation every camera must do
      • The countermeasure question — shielding and workload smoothing — is now part of camera design
    Source: usenix.org · Discuss: HN Discuss · 208 pts / 43 comments

    What HN commenters are sayingShort, impressed thread. The first question is simply who can build one. Commenters are surprised EMR fluctuations are usable from metres away and suspect weak shielding in current products does much of the work — implying vendors could mitigate it. The sharpest technical probe asks whether a deliberately crude codec that dumps near-raw pixels would flatten the workload variation and evade detection. Others note the national-security and corporate-espionage value. Nobody disputes the paper's reported results; the argument is about how long the advantage lasts once camera makers care.

    Pointing AI at 400 years of archives surfaced a forgotten meteorite, three lost rhinos and unrecorded eruptions

    Jesse Waites replicated and extended a recent dodo-discovery method: embed millions of Dutch East India Company pages (4.35 million, via the GLOBALISE transcriptions) and digitised newspapers into searchable meaning, screen candidates with a cheap decision model (Jev), read survivors with a larger model, and verify every claim against the original scan and specialist catalogues. One overnight run did the archive pass. Reported finds: an 1812 meteorite fall in Maharashtra absent from six catalogues, three Javan rhinos shipped toward Kandy in 1738–1740 that all died en route, and eruptions missing from the standard volcano list. The workflow is open-sourced as a toolkit called Antiquity.

    • The pipeline
      • Semantic search over 5.7 million passages handles 17th-century spelling chaos that defeats keywords
      • Cheap model screens tens of thousands of hits (about $3 for 59,000 elephant mentions); larger model reads the flagged few dozen
      • Controls first: the pipeline had to rediscover known events — the dodo account, Laki, Tambora — before its new finds counted
    • The finds (author-reported, catalogue-checked)
      • 1812 Maharashtra meteorite: would predate the region's earliest recorded fall by 26 years once confirmed
      • Three Javan rhinos, 1738–1740: documented with dates, a named ship and sworn crew statements; none reached Kandy
      • Volcanic eruptions witnessed by Company officials but absent from the Smithsonian list
    • Why it matters
      • The verification discipline is the transferable part: every claim ends at a checkable original page
      • Archives at this scale are newly searchable — the bottleneck moves from reading to judging
    Source: jessewaites.com · Discuss: HN Discuss · 163 pts / 82 comments

    What HN commenters are sayingPraise with one aesthetic revolt: a commenter calls the page's rotating rhino and animated effects unnecessary cruft that makes serious work look satirical — the author replies in-thread that he has added a button to turn the effects off. A second project doing similar structured extraction over modern political media asks whether heavy preprocessing is worth co-investing in for historical documents. The sceptical note asks how much the author himself learned about the Company when a machine did the reading — junk-food calories is the charge — while others simply link the original dodo post that inspired the whole thing.
