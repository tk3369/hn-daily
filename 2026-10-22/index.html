    Meta ordered to pay $25B in New Mexico Cambridge Analytica case — cut from a $219.5B calculation, 15% interest running

    A Santa Fe jury found Meta liable in September 2026, and Judge Francis Mathew of the New Mexico District Court set the penalty in a filing revealed 21 October: $25 billion. The jury found more than 43 million violations of New Mexico's Unfair Practices Act, each carrying up to $5,000 — a $219.5 billion calculation the judge reduced to $25 billion, with interest at 15% a year until paid. The claims: Meta misled New Mexico users about how it safeguards and collects data and prevents harmful material, and Facebook never ran the comprehensive investigation it promised after Cambridge Analytica — the judge called the internal examination willfully ineffective, citing cost pressure from senior executives and thin enforcement resources. The suit was filed in 2021 by former AG Hector Balderas; current AG Raul Torrez oversaw the trial. New Mexico was not part of the separate multi-state settlement in August, so its case went to trial. Meta chief legal officer C.J. Mahoney said the company is confident it will prevail on appeal, that the ruling makes doing business in New Mexico all but impossible, and that the suit amounts to a tax on speech.

    • The numbers
      • 43 million-plus Unfair Practices Act violations at up to $5,000 each; $219.5B calculated, $25B ordered, 15% annual interest until paid in full
      • Context from the same report: Meta paid $725M in 2022 to settle the Cambridge Analytica class action, and New Mexico's separate child-safety case produced a $375M jury ruling in March plus a $567M abatement fund order
    • Why it matters
      • Going it alone paid off on paper for New Mexico versus joining a combined settlement — but an appeal is certain, and the collectable number is the appeal outcome, not the headline
      • The per-violation arithmetic is the mechanism to watch: at platform scale, a $5,000 unit penalty becomes a company-sized number without any single decision being that large

    LiteLLM 1.107.0 on PyPI shipped a credential stealer and an hourly backdoor — second compromise for the project

    SafeDep reports that LiteLLM 1.107.0, published to PyPI on 21 October, carried malware in all seven wheels. Installing it placed three files in site-packages: cook.pth, which runs a credential stealer (cook.py) at every Python startup — even in processes that never import litellm — and sitecustomize.py, a daemon that re-runs the stealer hourly and downloads and executes code from a server whose address it reads from a GitHub file. The stealer collects SSH keys, cloud and CI/CD credentials, browser passwords, and the LLM provider keys stored in a LiteLLM proxy database, encrypts them, and posts them to a lookalike domain. LiteLLM's own incident report, per SafeDep, says the attacker held GitHub CLI credentials of three developers — believed taken from logs of an internet-exposed internal LiteLLM deployment — bypassed branch protection with an owner's token, pointed the private release workflow at a lookalike repository, and had the official pipeline build, sign and publish the artifacts. PyPI removed 1.107.0 by 13:23 UTC; malicious Docker images (v1.107.0, latest, main-latest, main-stable) were live 11:46-14:20 UTC. Versions 1.106.2 and the 1.107.0 release candidates are clean. The backdoor's GitHub account was deleted by 13:40 UTC, so the daemon now finds no server — hosts that ran it earlier could have received second-stage code.

    • Check now
      • Indicators: cook.pth, cook.py or an unexpected sitecustomize.py in site-packages; /tmp/.pc_once_72129118c59f5636c0bb or /tmp/remote_code_loader.lock on disk; if 1.107.0 was installed anywhere, rotate the credentials that host could reach — the stealer's target list is the rotation list
      • Pin to 1.106.2 or another explicit earlier version per LiteLLM's guidance quoted in-thread; the upstream GitHub source does not contain the malware, so source installs and wheel installs diverged
    • Why it matters
      • The attack ran through the project's own signed release pipeline, not a typosquat — provenance checks that trust the publisher do not catch a compromised publisher
      • A .pth file plus sitecustomize means persistence at interpreter startup, not import time: uninstalling the package intent is not the same as verifying the three planted files are gone
    Source: safedep.io · Discuss: HN Discuss · 557 pts / 182 comments

    What HN commenters are sayingReaction is dominated by one word: again. Commenters note this is LiteLLM's second compromise and call a repeat malpractice, while others wish the team well and immediately pitch or seek alternatives. The practical proposal with the most support is boring and effective: package managers (uv, npm, pip) should default to a 24-48 hour cooldown on new releases so a yanked-within-hours malicious version is never installed by default. A second thread of anger targets an in-thread quote from LiteLLM's issue tracker — enterprise customers on a private registry were told they are unaffected and are receiving an embargoed fix for a separate vulnerability — which readers call terrible optics mid-incident.

    Railway disclosure: attacker may have read decrypted customer env vars — roll every secret, builds paused

    Railway disclosed on 21 October that it detected anomalous activity involving the systems that store customer environment variables, and that an unauthorized third party may have accessed encrypted environment variables and, for some, obtained the decrypted contents. Env vars are where customers keep API keys and database and registry credentials. Railway says it believes this is part of a series of attacks targeting platform companies with the aim of compromising AI inference providers, and that it has notified upstream providers to revoke keys proactively. Its instruction is unconditional: immediately roll all environment variables stored in Railway, including API keys and private registry credentials, and review logs of those services for unusual activity. All deployments are paused during the investigation, so new versions cannot ship until builds are restored. Railway says impact may be limited to a subset of users, but it is treating rotation as a precaution for everyone and will email confirmed-affected accounts directly as it narrows scope.

    • What to do if you use Railway
      • Rotate secrets at the source service, not just in Railway's UI, and check those services' logs — commenters in Railway's Discord report Railway-only keys already being used by third parties, which is user-reported, not Railway-confirmed
      • Expect a shipping freeze: deployments are paused while the investigation runs, so plan releases around restored builds, not around your own rotation finishing
    • Why it matters
      • A platform's env-var store is a concentration of other companies' keys: one read path reaches every tenant's upstream accounts at once, which is why the stated target — AI inference providers — matters beyond Railway itself
      • The disclosure is early and thin on mechanism (how encrypted values were decrypted is not explained), so the rotation advice has to be taken on trust while details are pending
    Source: blog.railway.com · Discuss: HN Discuss · 525 pts / 303 comments

    DuckDB 2.0.0 LTS 'Cinnamon Teal': client-server Quack, async I/O, first-class VARIANT, triggers, agent mode

    DuckDB 2.0.0 is a long-term-support release (supported until at least October 2027), built from close to 20,000 commits since 1.5, and DuckDB calls it its biggest feature release so far. The in-process database grows a client-server mode: the Quack protocol is polished, a new CONNECT statement attaches and switches to a remote database in one command (including PostgreSQL and MySQL, with a remote pushdown optimizer), and the CLI gains -serve / -connect shortcuts. Asynchronous I/O for Parquet, CSV and native storage keeps multiple remote reads in flight, aimed at object-storage queries. VARIANT becomes first-class: semi-structured data is shredded into columnar form so it compresses and executes like typed data, end to end through Parquet. The CLI detects coding agents (Claude Code, Codex, Cursor) and switches to an agent mode — compact Markdown tables, explicit truncation notices, early stop on runaway queries, JSON errors, and pre-run cost estimates; DuckDB says agent mode cut model-read output by 59% on TPC-H in its experiments. Also in: a PEG-based extensible SQL parser as default, triggers (BEFORE/AFTER, row and statement level, usable for incremental materialized-view maintenance), a revamped C API v2, and trusted extension repositories. 1.5 support is extended to March 2027 and 1.4 LTS runs to 17 November 2026.

    • Upgrade notes
      • The new parser is designed to be compatible, with deliberate changes listed in the migration guide; the old parser remains available via the legacy_parser extension (SET enable_legacy_parser = true)
      • Some clients (R, Rust) and extensions lag the core release by days — check your client before planning a same-day fleet upgrade
    • Why it matters
      • Quack plus CONNECT moves DuckDB from embedded library toward shared analytics server — the role commenters say they already run alphas in — without giving up the single-binary deployment story
      • Agent mode is a sign of the times made concrete: a database CLI now treats LLM token budget as a first-class output constraint, with measured savings

    Apple reversed icons-in-every-menu: Tahoe shipped it, Golden Gate removes it, and the HIG now warns against it

    Jim Nielsen notes that macOS Tahoe's approach — an icon on every menu item by default — is gone in the next macOS ('Golden Gate'), and Apple's updated Human Interface Guidelines now use Tahoe's menus as the example of what not to do: menu items should have uniform visual treatment, with icons used consistently rather than on everything. John Gruber reported the reversion in June. Nielsen's point is about persuasion, not pixels. He had previously argued against icons everywhere and leaned on 'Apple doesn't do it' — an argument Tahoe destroyed. The replacement argument is stronger: Apple designed it, shipped it, lived with it for a year, then publicly changed its guidance. Choosing not to do something you have never done is preference; choosing not to do something you have done is experience. The post is short and links his original critique and Gruber's coverage.

    • What changed
      • Tahoe (macOS 26): icons in every menu by default. Golden Gate: that default is removed, and the HIG explicitly shows the icon-everywhere menu marked incorrect versus the uniform menu marked correct
      • The guidance is about scanability and consistency — a menu where some items have icons and some do not, or all do by force, is harder to read than a uniform list
    • Why it matters
      • Platform HIG reversals are rare and useful: they convert a taste argument into a documented, shipped-and-regretted experiment that design teams can cite without relitigating it
      • It is also a Tahoe verdict in miniature — commenters connect it to Liquid Glass and ask how much of that release the next one will quietly undo
    Source: blog.jim-nielsen.com · Discuss: HN Discuss · 389 pts / 225 comments

    What HN commenters are sayingNot everyone forgives. The top response calls the conclusion too generous: a more persuasive pitch would have been the judgement not to ship the mess in the first place. A longer diagnosis blames generational turnover in UI design — new designers discarding old principles without learning why they existed (Chesterton's fence), compounded by inspiration sites rewarding novelty. The design debate itself splits: meaningful icons for frequent actions genuinely help scanning and muscle memory, say defenders, while the uniform-shape icon trend (every icon in the same rounded blob) destroys the distinctiveness that made icons work.     A group calling itself FulcrumSec published a post claiming it exfiltrated 10.6 TB from PingCAP's TiDB Cloud over roughly two months, and released a first stage of about 200 GB. Treat every figure as attacker-claimed and unverified: 4.9 million files, 180,046 tenant organisations, 403,262 unique emails, 115,308 plaintext console API keys (42,612 claimed active), 20.6 million customer SQL statements captured by the product's SQL editor, 102 million gateway connection records, 377,446 Jira issues, 433,928 CRM contacts, and 413 private source repositories. The claimed method matters more than the totals: credentials committed in PingCAP's own repositories (GCP service-account keys, an Azure service principal) allegedly let the attackers stand up a replication feed of the control-plane database that re-exported every table every six hours for 22 days — 88 consecutive exports, undetected, per the post.     • Grade the claims

    WorldTUI: a 360M model pretends to be a terminal — no shell, no filesystem, runs in your browser at 208 MB

    Simon Edwards fine-tuned Qwen2.5-Coder-0.5B into WorldTUI, a 360M-parameter model that simulates a terminal with nothing behind it: every keypress goes in, and the model predicts how the screen changes — files, vim, tmux and snake included. The trick is representation: the terminal is a grid, the model outputs row rewrites plus cursor position in a 333-token vocabulary with grammar-constrained decoding, and a COPY operation makes scrolling cost 3 tokens per row instead of about 96. Training data is synthetic and perfectly labelled — real programs run in Docker, 336k episodes, roughly 2B tokens, with randomised personas, files and a 1.2% typo rate. The biggest quality win was DAgger-style self-repair: let the model predict, diff its screen against the real one, and train it to fix its own mistakes next keypress (PresetBench rose from 24/47 to 38/47 at int4). Parallel row decoding plus speculative verification cut large-frame p95 latency from 6.7s to 0.87s on an RTX 4090; typing is about 60ms per character in the browser on an M4 Mac. Total training was about 75 GPU-hours on one RTX 4090. Scores: 80/106 on ShellBench versus 52 for the prompted base model, and 9/13 file readbacks versus 2-3 — memory works, but is far from a reliable filesystem (append a line, then cat often misses it). Distillation taught the sharpest lesson: removing one layer barely moved next-token accuracy (99.3% to 98.9%) while exact memory readbacks collapsed from 64/64 to 0/64. The browser demo is 208 MB at int4, WebGPU, all local.

    • The measured results
      • ShellBench 80/106 (base model prompted: 52); memory readbacks 9/13 versus 2/13 and 3/13 for prompted baselines; large-frame p95 latency 6.7s sequential to 0.87s with parallel rows
      • About 75 GPU-hours on a single RTX 4090 for the model and its refinements — a one-person world-model experiment, not a lab-scale run
    • Why it matters
      • It is a clean test of the world-model question in miniature: plausible output is easy, consistent state is the hard part — and the gap is measurable in readbacks, not vibes
      • The layer-7 result is a warning for all model compression: a student can look identical on token accuracy while quietly losing the exact capability you cared about

    Google publishes its Rust style guide: small crates, no glob imports, prefer borrows, expect over unwrap

    Google has published the Rust edition of its long-running style-guide series, covering the Rust used across google3, Android, ChromeOS, Fuchsia and Chrome. It explicitly builds on the public Rust Style Guide and API Guidelines and deviates where Google's scale demands it — the stated extra goal is smoothing Large-Scale Changes: codebase-spanning, tool-assisted refactorings that need deliberate, refactor-friendly patterns. Concrete rules: prefer small crates (in Chromium, ideally a single file focused on one abstraction) with a flat file layout, name leaf modules after their primary item, do not implement APIs in non-leaf modules, no glob imports, one module per use statement, locally-scoped trait imports. Ownership guidance: avoid Rc and Arc, prefer borrows over deep copies, accept flexible references and Into, prefer enum over bool in APIs, prefer named fields over tuples. Implementation rules include prefer expect over unwrap, pattern matching over check-then-unwrap, no iterator chains when a plain loop is clearer, and use format!/write! for substitution. Codebase-specific rules are tagged in the guide — Chromium gets 'do not use async/.await' and 'do not start threads through the standard library', Fuchsia gets its own mutex rule. Library-code API rules are binding; for application code they are a strong recommendation, and the guide says so explicitly.

    • Rules worth stealing
      • Enum over bool in APIs, newtypes over aliases, #[non_exhaustive] on public enums and structs, #[must_use] discipline, options structs implementing Default, and pairing important From impls with named constructors
      • The LSC lens: several rules exist not because the alternative is ugly, but because a tool must be able to rewrite a million files safely — a criterion most style guides never state
    • Why it matters
      • A public, coherent guide from a top Rust employer ends the reverse-engineering era — commenters describe previously distilling Google/Meta style by prompting LLMs over fmt and clippy configs
      • It is also a maturity marker: Rust at Google is now large enough to need the same governance C++ got, tags for divergent codebases included
    Source: google.github.io · Discuss: HN Discuss · 344 pts / 203 comments

    What HN commenters are sayingThe thread argues rule by rule, which is the compliment. The Rc/Arc ban draws the strongest dissent: one commenter says use Arc freely for anything living outside the call stack instead of fighting lifetimes, and suspects the rule is C++ reference-counting trauma. Unqualified type imports split readers too — IoError instead of io::Error loses context, says the cargo-team voice in-thread. Getters and setters provoke a naming fight in both directions. The meta-takes land alongside: style guides now exist mainly to be fed to an LLM, Google's brand no longer makes its guidance gospel, and the library-versus-application distinction earns genuine praise for defusing Rust's generic-code reputation. A practical tip surfaces: rust-analyzer's prefer_underscore_import attribute makes extension-trait imports painless.
