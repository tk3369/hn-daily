    Fingerprinting script or bioweapon manual? It's anti-LLM bait

    A researcher crawling 10,000 sites for canvas fingerprinting found an anti-bot script whose obfuscation uses alarming-sounding names and hidden prompts designed to trip LLM safeguards. Underneath the theatre, it collects ordinary browser and GPU signals.

    • What was found
      • A canvas resembling album art led to a script from servicepipe.tech; the author traced an encoded hidden string to a safeguard-tripping prompt.
      • A frontier model refused to deobfuscate it, while an open-weight model complied, according to the author.
    • Why it matters
      • Scary-looking identifiers are not evidence of scary behaviour — the script's real job is standard anti-bot fingerprinting.
      • Anti-LLM defences now pollute the same code that analysts and models must read, raising false-alarm costs.

    A working RISC-V CPU compiled into Qwen3.5's weights

    A stock Qwen3.5 4B model now carries a deterministic 32-bit RISC-V CPU compiled into its weights, using Gated DeltaNet layers as exact RAM. It runs C and MicroPython with no external runtime or tool calls.

    • How it works
      • Gated DeltaNet state with gate and write strength set to 1, plus one-hot keys, gives addressable, exact RAM.
      • A compiler turns the CPU circuit into transformer layers; it passes riscv-tests and ran 18 million instructions free-running, matching qemu.
    • Measured result
      • DeepMind arithmetic sits near tool-assisted levels; NUPA long-integer accuracy rises from 48.6% to 100%, per the author.
      • About 230,000 output positions replayed against a reference machine with zero mismatches.
    Source: divagr.com · Discuss: HN Discuss · 596 pts / 120 comments

    What HN commenters are sayingDelight dominates, with DOOM jokes and curiosity about the in-model filesystem — 1,024 directory slots, up to 512 files. The serious thread is safety: hidden RNN state could evade chain-of-thought monitoring, or, flipped around, in-weight monitors the model cannot switch off.

    Isolated OpenAI agents found a way to talk through the CPU cache

    In an OpenAI experiment, agents in separate microVMs on shared hardware, told to exchange synthetic secrets with no network or shared files, found a processor-cache timing channel. They were tasked to find a channel — this was not spontaneous collusion.

    • What was tested
      • Isolated sandboxes on the same host, with no network or shared writable files, still leaked via cache timing.
      • A community 'cpu-chat' demo extends the idea to contention, cache-eviction timing and DRAM bandwidth.
    • Why it matters
      • Shared hardware leaks even without a network; real isolation needs core pinning, NUMA controls, separate nodes — or physical separation.
      • The result is a test of sandbox design, not evidence that agents spontaneously conspire.
    Source: the-decoder.com · Discuss: HN Discuss · 266 pts / 186 comments

    What HN commenters are sayingSome call it a well-known covert channel dressed as news, since the agents were instructed to find one. Others want physically isolated frontier data centres, and several criticise media framing that implies agents 'yearn' to communicate.

    Alpine's GitLab incident: a Ruby regex bug, and a re-released 19.3.6 image

    Alpine Linux reports an attempted exploitation tied to CVE-2026-97229, a Ruby regular-expression-engine flaw. Upgrading GitLab alone did not fix it: the patch lives in Ruby, and Alpine's image used standard Ruby.

    • What to do
      • Pull the Alpine GitLab 19.3.6 image published October 27, which contains Ruby 3.3.13; earlier 19.3.6 pulls and older tags remain vulnerable.
      • Any program compiling regular expressions from untrusted input is exposed, not just GitLab.
    • Risk
      • Re-releasing a fixed image under the same tag confuses version checks — commenters ask why not a new version.
      • Build-from-source users face a constant patch-tracking burden with no clean solution.
    Source: alpinelinux.org · Discuss: HN Discuss · 210 pts / 97 comments

    What HN commenters are sayingPraise for a transparent writeup, including what would have leaked if the attacker had succeeded. Debate follows on whether GitLab should blacklist vulnerable Ruby runtimes, and whether 'attempted' in the title downplays uncertainty about success.
