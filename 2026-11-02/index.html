    HackerTube still tops HN: YouTube rebuilt from videos HN itself recommended

    Karpathy's HackerTube puts a YouTube-style interface over 6,454 videos pulled from 39,834 HN comments since 2007. It is still the day's runaway story: curation by HN's own taste, not an engagement algorithm.

    • What it is
      • A catalogue sourced entirely from HN comment recommendations, with the underlying data downloadable from the site's about page.
      • Built largely with Claude: about 504M input tokens (90% cached) and 7.6M output tokens, mostly Sonnet labelling comments, with the app itself roughly 1M Opus tokens.
    • Why it matters
      • It is a working answer to algorithmic-feed fatigue: curation by a community you already trust beats curation by retention metrics.
      • It also prices the new normal — a side project can cost hundreds of dollars in model calls, prompting calls for a 10–100x cheaper Sonnet-class decision model.
    Source: karpathy.bearblog.dev · Discuss: HN Discuss · 2726 pts / 602 comments

    What HN commenters are saying: Cost still dominates: the author puts the Sonnet labelling near $300, others say it fits several times over in a $20 subscription, and several ask for a cheaper decision model. Others want the same treatment for kids' content and social feeds, and several ask where to download the data — the author points to the site's about page.

    HackerBooks does HackerTube for books — 16,500 books HN actually mentioned

    HackerBooks, inspired directly by HackerTube, catalogues about 16,500 books mentioned by at least two different HN commenters since 2007, each linking back to the comments that mentioned it. The author says Claude Opus 5.5 wrote almost all of it, including the data pipeline.

    • How it works
      • Plain JavaScript and static JSON on Cloudflare: a small top-books index up front, the full list loading behind it, covers on R2, data from the HN dump via Python and DuckDB.
      • The homepage shuffles its books daily, and each book page links back to the HN comments that mentioned it.
    • The catch
      • It counts mentions, not praise — trashing a book counts the same as recommending it, so the ranking is “most mentioned”, not “most loved”.
      • The author is upfront about this in the post itself, and commenters immediately propose splitting the two rankings.
    Source: hackerbooks.org · Discuss: HN Discuss · 1679 pts / 278 comments

    What HN commenters are saying: Speed is the first reaction — commenters praise sub-second paints and a tiny payload, with one posting detailed lab timings. The second is the mentions flaw: a high ranking for Ayn Rand prompts jokes and a call to split “most mentioned” from “most recommended”, plus bug reports on the “mentions since” filter.

    Postgres 19 is late because AI review is finding bugs faster than humans can fix them

    Postgres 19 is delayed, and the blog's argument is that AI-assisted review is surfacing far more bugs than before. Discovery is no longer the bottleneck — the small maintainer group that must validate reports and review fixes is.

    • Why now
      • AI review gives a tight, deterministic feedback loop on “find the bug” tasks, unlike open-ended “write the feature” work, so reports pile up.
      • The same asymmetry is why analysis tools can scale where generation cannot: the checker is cheap, the human verdict is not.
    • The correction
      • Commenters stress the code itself was not AI-written — AI helped review and find bugs, so this is not a “slop” story; it is a verification-capacity story.
      • If anything, the delay is evidence the review process works: bugs that would have shipped later are being caught now.
    Source: rhaas.blogspot.com · Discuss: HN Discuss · 670 pts / 409 comments

    What HN commenters are saying: The thread splits on whether this is good news or a warning: finding bugs earlier is strictly better, say some, while others note AI only adds work if fixes still need humans. Several argue the real lesson is to point AI at analysis and verification first, where the loop is checkable, rather than at generation.

    Ask HN: is there a TV that respects privacy? The answer is mostly “don't connect it”

    The asker wants a 60–80-inch 4K TV at 60Hz or better, is happy to pay a premium, and wants it to be nothing but a display for an Apple TV. The honest HN answer: no brand earns full trust — the privacy comes from how you set it up.

    • The consensus setup
      • Buy on panel quality, never connect the TV to the network, and run everything through an Apple TV or a local media server like Jellyfin.
      • The purist version is a dumb large monitor with no smarts at all — no account, no telemetry, nothing to update.
    • The disagreement
      • Whether an unconnected TV can still phone home via neighbours' Wi-Fi, Bluetooth mesh or Amazon Sidewalk — some call that unproven, others say untrustworthy hardware should be treated as compromised anyway.
      • A practical warning: some sets nag constantly, or refuse to work properly, without an account and a network connection.
    Source: news.ycombinator.com · Discuss: HN Discuss · 546 pts / 658 comments

    What HN commenters are saying: The top advice is blunt — “none” and “keep the glass disconnected forever” — but the thread then argues about the edge cases: sets that nag or refuse to work without an account and network, guests connecting a TV to a phone hotspot, and whether Sidewalk-style mesh links are a real TV risk today or a theory without a documented case.

    Lenovo's “encrypted” fingerprint USB is, per a teardown, just an unencrypted SD card in a case

    A teardown report linked from Reddit finds Lenovo's fingerprint “encrypted” drive stores data on an ordinary, unencrypted SD card behind the fingerprint gate. Remove the gate and the data is there — the encryption claim, on this report, is not a storage property at all.

    • Why it matters
      • Hardware encryption you cannot audit is a trust claim, not a verified property — the user has no access to the engine or the raw storage format to check it.
      • That is the difference between “encrypted” as a marketing label and encryption as something you can verify with independent implementations.
    • The alternative
      • Open software cryptography on ordinary storage, where the algorithm and output can be checked, or keypad drives that unlock before plugging in.
      • One detailed commenter names Apricorn keypad drives as the better-tested option, with a battery so you can unlock before the USB rail is even live.
    Source: reddit.com · Discuss: HN Discuss · 523 pts / 168 comments

    What HN commenters are saying: Commenters call this worse than a bad implementation — no security at all, not weak security — and note the compliance angle: some buyers were required to use such drives by regulation, not choice. The broader thread distrusts black-box hardware encryption generally, while others counter that phones' inline crypto engines are validated the same opaque way.

    The AI cost of JavaScript frameworks: Astro is cheapest to have an agent build

    Nolan Lawson's benchmark has AI agents build the same app in different JavaScript frameworks and measures time and tokens. Astro comes out on top on time, second-lowest on spend, with zero client-side JavaScript — a tax schedule for framework choice in the agent era.

    • What won and why
      • Content-driven apps suit Astro's server-rendered, low-JS model; commenters confirm it is pleasant in practice, with escape hatches — including React islands — when real interactivity is needed.
      • That is the practical version of the benchmark: pay the model to wade through as little client machinery as possible.
    • The caveat
      • The benchmark app is small and content-driven, so it flatters Astro; an interactive, realtime, form-heavy app could reorder the table.
      • SolidStart's new V2 gets praised in the thread for exactly that case, and framework choice also turns on maintainability and team knowledge.
    Source: nolanlawson.com · Discuss: HN Discuss · 422 pts / 322 comments

    What HN commenters are saying: Astro users confirm the result from experience, while sceptics attack the benchmark's scope rather than its numbers: a to-do-style app is light-years from a commercial product, framework choice also turns on maintainability and team knowledge, and several commenters simply relitigate Angular — loved by some, “always at the bottom” by others.

    OccupySaaS: laid-off engineers rebuilding SaaS in the open, starting with Auth0 and Salesforce

    OccupySaaS is a protest movement written in code: laid-off engineers using AI and public documentation to build clean-room, open-source, drop-in replacements for per-seat SaaS. Its first two targets are identity (ZeroAuthy, Auth0-compatible) and CRM (SalesCompel, Salesforce-compatible), both early and Apache-2.0.

    • The method
      • Specs written from public API docs and open standards, builders kept behind a clean-room firewall from spec writers, AI implementing from the spec alone.
      • Compatibility is proven by running the vendors' own public SDKs against the replacement — if existing code does not work unchanged, it is not done.
    • The catch, stated on the site
      • Neither project is production-ready yet — early, with only a slice of each API working, and the site itself says to try them, break them, and file issues.
      • Per-seat pricing and lock-in are the grievance; a compatible open alternative is the proposed answer, not just a cheaper clone.
    Source: occupysaas.com · Discuss: HN Discuss · 413 pts / 257 comments

    What HN commenters are saying: The thread splits between enthusiasm for the idea and doubt about the execution: some call anger a poor substitute for product vision and note open-source CRMs predate AI without taking off, while others argue per-seat pricing and lock-in are exactly why a compatible open alternative matters. A recurring jab: funding the AI vendors with subscriptions while fighting the layoffs AI caused.

    Mathematics has changed — Calegari, on Tao's blog: reward the question, not just the theorem

    In a guest post on Terry Tao's blog, Frank Calegari argues OpenAI's October 6 release of over 700 claimed research papers is a watershed: AI can now make groundbreaking contributions across mathematics, so the profession should change how it hires, publishes and trains — starting with evaluating every paper as if it were AI-assisted.

    • The proposal
      • Hire on in-person conversation and a narrative of where mathematics should go, not a paper file; demand journals adapt or abandon them.
      • Put more weight on breadth in graduate training and on seminars, and give senior mathematicians the job of creating future problems, not just answering existing ones.
    • The warning
      • A rush to be first to publish AI-assisted proofs creates a gulf between producing proofs and understanding them.
      • Choosing worthwhile problems and developing new directions may matter more than producing the proof itself — and the current reward structure undervalues exactly that exploratory work.
    Source: terrytao.wordpress.com · Discuss: HN Discuss · 345 pts / 437 comments

    What HN commenters are saying: Commenters divide on whether AI can invent or only recombine: some say paradigm shifts and novel techniques remain unproven for machines, others say trillions in investment tend to produce breakthroughs. The practical thread is about Lean and formalisation — a checked proof still depends on the human-written specification, and a bug in the formal statement can “prove” the wrong theorem.

    OmniDiff: a content-aware Git difftool in Rust that handles moved code properly

    OmniDiff diffs code in 25 languages plus config, images, PDFs, archives and fonts, and the author says it can diff tens of thousands of lines of C++ in under 100ms on a 2023 ThinkPad. It is built from 2,000 real diffs sampled across Gentoo-listed repositories, and it is AGPLv3, at v0.3.0.

    • Why it differs
      • Language-aware diffing treats moved code as moved, not as deleted-here and inserted-there; the author reports it is perfect on 90% of diffs it shares with difftastic, versus 64% for difftastic, and much faster at the median.
      • It also diffs the non-code majority of real diffs — config, images, PDFs — that code-only tools skip.
    • The licence fight
      • The author chose AGPL deliberately as a political choice against big-tech adoption; critics say that kills the project in infancy and that a permissive fork will win.
      • The author answers that inspiring a better differ, even under another licence, is still a win for the open-source community.
    Source: github.com · Discuss: HN Discuss · 287 pts / 90 comments

    What HN commenters are saying: Comparisons to delta and difftastic dominate: delta only colours standard git diff, say commenters, while OmniDiff changes the algorithm — but several want side-by-side view on wide terminals and more packaging. The AGPL thread is the longest argument, including whether AI-assisted code can even carry a copyleft licence at all.

    Point your camera at a landscape and learn its geology — AR maps, deep time included

    Outcrop paints geologic maps over the landscape through your phone camera, identifying the mapped rocks, describing them, and rewinding continent positions to show the Earth as it looked when those rocks formed. It grew out of the author's Flyover Country app for airplane-window geology, and it is out on Android with iOS in TestFlight.

    • What to try
      • The “where it formed” view is the crowd favourite — including with kids — plus soils and quaternary layers for areas with little bedrock exposure.
      • Maps and the main view work offline; fossil finds and live fault data still need a connection.
    • The rough edges
      • Some Android phones fail to start motion tracking, and commenters ask for a web version instead of another app install.
      • The landing-page copy also takes criticism — several commenters call it AI-smelling, and the author asks for more examples of what rings false.
    Source: outcrop.rocks · Discuss: HN Discuss · 234 pts / 48 comments

    What HN commenters are saying: The reaction is warm — families report hours down the rabbit hole — but practical requests pile up: a web version, importable ASTER and Landsat data layers for field geology, and a fix for the marketing copy, which several commenters call AI-smelling. The author takes the copy criticism on the chin and asks for more examples of what rings false.
