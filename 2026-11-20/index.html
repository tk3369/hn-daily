Frostbite: an AI-designed CPU that claims 4.59× perf-per-watt

Architect Labs says its AI systems designed, verified and took to GDS a new general-purpose CPU built on interaction nets — no shared mutable state, so parallelism falls out of the program instead of being dug out by out-of-order hardware. The headline is 4.59× performance-per-watt over 25 workloads versus a dual-issue in-order core: a modest baseline, and pre-silicon numbers, so read the multiple as a claim, not a measurement.

Source HN Discuss 352 pts · 228 comments
What HN commenters are saying

The thread splits between the value chain and the verification. Several argue the HDL was never the hard part — the bottleneck is fabs, materials and manufacturing, and ask why the ASI wouldn't just design a TSMC too. Others say the formal verification is the real story: 800k+ lines of Lean contracts as the single source of truth is a stronger claim than the perf number. The 4.59× figure gets the usual caveat — it is against an in-order baseline, on the vendor's own workloads.

MIT's free 'How to CAD Almost Anything' course, in full

MIT OpenCourseWare published the complete IAP 2024 course on CAD — lectures and material for going from zero to designing real parts. It is a solid grounding in traditional CAD, but don't expect AI-assisted workflows: the course predates them, and the thread's practitioners say the hard part was never the tooling anyway, it is design judgment — tolerances, draft angles, what will actually change.

Source HN Discuss 325 pts · 109 comments
What HN commenters are saying

Practitioners call the course a good intro to traditional CAD, but the AI question dominates: at even very AI-forward companies, the consensus is AI-first CAD isn't production-ready yet. The hard part, several working MEs repeat, is mechanical design itself — design-for-manufacturing checks, tolerances, and parametric models that anticipate what will change — not drawing the geometry. One builder in the thread is working on exactly that gap and asking what to fix first.

OpenSSL buffer overflow in EVP_EncodeBlock — CVSS 9.8, fix not yet merged

A buffer overflow in EVP_EncodeBlock(), OpenSSL's base64 encoder, is rated CVSS 9.8: a crafted length can overflow the output-size calculation. A fix PR guards the encode/decode paths and the HTTP client's base64 helper, but it's still open and the advisory is pending. The thread's one comfort: no enterprise distro has shipped OpenSSL 4, where the affected AVX2 path lives — check your own builds, don't assume you're clear.

Source HN Discuss 320 pts · 268 comments
What HN commenters are saying

Patch fatigue is the mood — 'I really need a day off from patching servers' — with several noting this follows a run of out-of-band patches. The technical question is what the 9.8 actually means in practice, and one commenter draws the parallel to Java4Shell: another base64 encoder with attacker-controlled lengths. The mitigating read is that no enterprise distro has shipped OpenSSL 4, so the blast radius is narrow until it does.

'I can tell you wrote this yourself' — the case for imperfect prose

An essay argues that human writing is recognisable precisely by its imperfections — the odd typo, the uneven rhythm — and that flawless AI-polished prose now reads as a tell. The thread mostly agrees but lands on a middle ground: grammar checks are fine, full generation is where the voice dies, and several note that perfectly polished text was never proof of understanding in the first place.

Source HN Discuss 305 pts · 295 comments
What HN commenters are saying

The middle ground wins the thread: grammar and spelling checks are fine, full generation is where the voice goes, and several point out grammar checkers predate LLMs by decades. The sharpest disagreement is over the essay's core claim — one side says human imperfection is what drives change, the other answers that imperfection also means medical errors and false convictions, and 'perfect-ness is the enemy of human ingenuity' is a straw man when the stakes are real.

One cruise line emits 10× the sulphur oxide of all Europe's cars (2019)

A 2019 analysis found Carnival Cruises emitted ten times more sulphur oxide than all of Europe's cars combined — the ships burn heavy fuel oil, the thick, high-sulphur residue left after refining. The thread's pushback is that container ships run the same fuel and have done for decades; the difference is that nobody books a container ship for fun, so cruises draw the outrage while the cargo fleet draws a shrug.

Source HN Discuss 301 pts · 176 comments
What HN commenters are saying

The fuel is the story: heavy fuel oil is the cheapest, dirtiest residue of refining, and ships have burned it for decades — this is not news to anyone in shipping. The disagreement is about the framing: several say container ships are the same problem at larger scale and get a pass because civilization depends on them, while others say cruises are fair game precisely because they're discretionary. A side thread argues Carnival isn't even a luxury line — 'a two-star hotel that happens to float.'

PostgreSQL 19 is out — REPACK, planner advice, and JIT off by default

PostgreSQL 19 landed November 19 with a new REPACK command that reclaims space without blocking reads and writes, planner-advice extensions, auto-scaling I/O workers, and logical replication that no longer needs a restart. Two changes to note before upgrading: JIT is now disabled by default, and MD5 password auth draws a warning. The thread's advice is the usual: let it soak, wait for 19.1 for production.

Source HN Discuss 300 pts · 16 comments
What HN commenters are saying

Only 16 comments, and the whole thread is one question: should I wait for 19.1? The consensus is yes for critical production — more installs shake out more bugs — but test it now in staging, since load-specific bugs won't show up by waiting. One early tester calls it the most bug-free .0 release yet; another notes the real lesson is that if everybody waits for .1, nobody finds the .0 bugs.

If you can't explain it simply, you don't understand it (2017)

A 2017 piece restates the Feynman test: explaining something in plain language is the check on whether you actually understand it. The thread applies it to the present — Claude's explanations expose the same gap, since it is easy to judge code correctness but hard to judge a muddled document — with the counterpoint that confident simple explanations can be flat wrong, so simplicity is necessary, not sufficient.

Source HN Discuss 268 pts · 162 comments
What HN commenters are saying

The thread turns the piece on Claude itself: several say the gap shows up fastest when the model writes documents or organizes requirements, where correctness is hard to judge — code at least fails loudly. Others push back on the premise, noting people confidently explain things simply while understanding nothing, so the test cuts both ways. A practical note recurs: Feynman-technique skills for Claude Code exist, and forcing the model to explain is a decent check on its work.

Source HN Discuss 191 pts · 56 comments

The mood is wait-and-see: if the formalization checks out, it's the story of the decade; until then, it's a claim.

Jujutsu primer — the Git-compatible VCS that keeps winning converts

A primer on Jujutsu, the version control system that keeps Git repos but replaces the interface — working-copy commits, no staging area, operations as a log you can undo. Long-time users in the thread call it the first VCS they'd pick for a large monorepo, while the recurring objection is GitHub: Mercurial died partly on hosting incompatibility, and Jujutsu's answer is to stay Git-compatible underneath.

Source HN Discuss 177 pts · 115 comments
What HN commenters are saying

Two-year daily users vouch for it — one runs it on a large monorepo and calls it fantastic. The debate is the old one: whether GitHub compatibility decides a VCS's fate, with Mercurial's decline as the cautionary tale and Git's own break from CVS as the counter-example. Several note the thread conflates Git and GitHub, and that Jujutsu sidesteps the question by keeping Git repos underneath.
